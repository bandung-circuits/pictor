# Pictorial 插件实测清单（DSH Desktop）

> 目标：把"上传 → extract → 结构页出现 → 选结构 → advise → 选方案 → render"这条垂直切片在真实 DSH 环境跑通。
> 每步都有「预期现象」与「若不符，反馈什么」。反馈内容越具体，修复越快。

## 前置

1. 重启 DSH Desktop（让 profile 重新加载 bundles）。
2. 新建一个会话，确认左侧栏出现「Pictorial」标签页（带文档图标）。
3. 准备测试文档：仓库 `fixtures/example-zh.md`（合成示例，无版权问题），或任何自己的 md/txt。

> 加载自检：插件加载成功时会在 `~/.dsh/pictor/` 创建数据目录。
> 若重启后侧栏没有 Pictorial 标签页，且该目录不存在，说明 bundle 未被加载：
> 先查 `~/.dsh/profiles/desktop/package.json` 的 `dsh.profile.bundles` 是否含 `dsh-pictor`，
> 以及 `node_modules/dsh-pictor` 符号链接是否有效，把结果发我。

## 步骤 1：新建任务（预期 1 分钟内）

- 操作：Pictorial 标签页 → 新建任务 → 选择 `example-zh.md` → 创建并开始。
- 预期：任务列表出现卡片，徽标为「执行中」；会话里**不会**滚动文本回显（后台执行是设计约定）。
- 反馈若不符：
  - 卡片出现但创建就报错 → 把报错文本发来（可能是执行会话启动失败：模型链路或 agentLoop 不可用）。
  - 卡片都没出现 → 说明 client 没加载或 RPC 不通，把浏览器/开发者控制台报错发来。

## 步骤 2：结构页（预期 1-3 分钟）

- 预期：任务卡片徽标变「待选结构」，详情页出现候选结构卡片（id、一句话说明）。
- 反馈若不符：
  - 长时间停在「执行中」→ 点开「展开运行细节（debug）」把文件列表贴给我（重点看 11.extraction/ 下有什么）；
  - debug 里有 `structures.json` 但页面没渲染 → 结构和契约可能对不上，把文件内容发来。

## 步骤 3：确认结构（预期 1-2 分钟）

- 操作：勾选 1-2 个候选结构 → 「确认所选，进入方案设计」。
- 预期：徽标先后经历「执行中」→「待选方案」，方案区出现提案卡片（layout/style/intent/复杂度标签）。
- 反馈若不符：同上贴 debug 文件列表与 proposals 相关报错。

## 步骤 4：渲染出图（可选，取决于生图配置）

- 操作：「生图配置」填入接入信息（可用 openai-compatible 指向已验证端点，配置要点见会话内提示文件）→ 勾选方案 → 「渲染所选方案」。
- 预期：方案区出现 PNG 预览，徽标变「已完成」。
- 反馈若不符：
  - 提示条"尚未配置生图模型" → 配置没保存成功，把 config 弹窗内容复述；
  - 渲染失败列表出现 → 把错误文本发来（密钥/端点/模型名/尺寸都可能）。

## 步骤 5（选做）：双通道旁路

- 在详情页「讨论」框发一句自由对话（如"换个更活泼的风格试试"），观察编排器响应并继续。
- 预期：编排器按 orchestrator 蓝图先评估再行动，不跳过门控。
- 反馈：观察是否符合预期，特别是它是否擅自继续了流程（不应自动进入未确认的阶段）。

## 收尾

- 删任务：列表卡片右侧 ×（确认后连同 run 目录一并删除）。
- 退出验证：改动均在 `~/.dsh/pictor/` 数据目录；卸载 = 从 profile package.json 移除 `dsh-pictor` 依赖与 bundles 条目、删除 node_modules 符号链接。

## 常见失败速查

| 现象 | 最可能原因 | 反馈给作者的要点 |
|---|---|---|
| 创建即报错 | 执行会话启动失败（模型不可用 / agentLoop 异常） | 报错原文 |
| 一直「执行中」 | extractor 子智能体卡住或失败 | debug 文件列表 + 11.extraction/ 内容 |
| render 失败 | 生图端点、密钥或模型参数不匹配 | 错误文本（含 status code） |
| 徽标与内容不符 | 契约不齐（缺 structures.json/proposals.json） | debug 面板贴图 |
